# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Motuz is a web UI + REST API for large data transfers between on-prem filesystems and cloud storage (S3, Azure Blob, Swift, GCS, SFTP, Dropbox, OneDrive, Google Drive, WebDAV). All actual data movement is done by shelling out to `rclone`. Backend: Python 3.12, Flask 3 + flask-restx + Flask-SQLAlchemy 3 / SQLAlchemy 2 (psycopg 3) + Alembic + Celery 5 (RabbitMQ broker, results stored in the database). Frontend: React 18 + Redux + redux-api-middleware 3 + react-router 5, bundled with webpack 5 (Node >= 22.15).

## Architecture

### Backend request flow (`src/backend/api/`)
`views/*_views.py` (flask-restx `Namespace` + `api.model` DTOs, mounted under `/api` in `application.register_api`; Swagger UI at `/api/`) → `managers/*_manager.py` (business logic, decorated with `@token_required`) → `models/` and `utils/`.

- **Auth**: `/api/auth/login/` checks username/password with PAM (`utils/pam.py`) against the host's users; the JWT identity is the Unix username. `JWT_IDENTITY_CLAIM = 'identity'` is part of the API contract (the frontend reads `state.access.identity`). Every token is checked against the `revoked_token` table, by its `jti` and by its session id (claim `sid`, shared by all tokens of one login). Access tokens live 15 minutes, refresh tokens 30 days (`JWT_*_TOKEN_EXPIRES` in `config.py`). `/auth/refresh/` rotates the refresh token: the old one keeps working for `REFRESH_GRACE_SECONDS` (60, `revoked_token.grace_until`) so tabs refreshing at the same moment both succeed, and reusing it later revokes the whole session. Logout revokes the refresh token and the session, i.e. every access token of that login. Tabs share tokens through localStorage; `middleware/authMiddleware.jsx` adopts tokens other tabs write (`storage` event) and re-reads them before refreshing and when a refresh fails, so a tab never uses a rotated refresh token. Postponed API calls resolve with their real result after a refresh.
- **Per-user scoping**: every model has an `owner` string column. Managers filter by `owner == get_logged_in_user(request)` and return 404 (not 403) for other users' objects. Jobs resolve their `src_cloud_id`/`dst_cloud_id` through `cloud_connection_manager.owned_cloud_id` so a job can never use another user's credentials. Connection create/update only accept columns in `_WRITABLE_FIELDS` (never `id`/`owner`), and an empty value for a secret field on update keeps the stored secret.
- **DTO secrets**: credential fields use `PrivateString` in the view DTOs, so they can be written but are never returned by the API.

### Filesystem access as the logged-in user
Motuz runs as root in the containers but every filesystem/rclone operation runs as the logged-in user via `sudo -E -u <owner> ...`, so local permissions are enforced by the OS. That is why the containers mount host `/etc`, PAM/SSSD/Kerberos config, and the shared filesystems (the Fred Hutch-specific mounts in `docker-compose.override.yml`; these must be added to both `app` and `celery`).

- `utils/rclone_connection.py` (`RcloneConnection`) — cloud ops. It runs `rclone --config=/dev/null` and passes credentials as env vars `RCLONE_CONFIG_<REMOTE>_<KEY>` (remote names `src`, `dst`, `current`) built by `_formatCredentials()` from a `CloudConnection` row. `_log_command()` masks credentials in logs using suffix allowlists (`should_log_full_credential` / `should_log_partial_credential`).
- `utils/local_connection.py` (`LocalConnection`) — same interface for the local filesystem (`ls`/`mkdir`/home dir via sudo). A `connection_id` of `0` in the API, or a `None` src/dst cloud on a job, means local filesystem.
- User-supplied paths must never be parsed as options: local commands put `--` before the path, and local rclone paths must be absolute (`_local_path`).
- **Listings** (`POST /api/system/files/`, `/files/home/`) return `{files, path}`. Local entries are `{name, type, size, modified}` (`type` `file`/`dir`/`symlink` = a broken link/`unknown`; `size` int or null) parsed by `_parse_ls` from `ls -a -l -L -g -o --time-style=+%s`; cloud entries are rclone's `lsjson` objects (`Name`, `Size`, `IsDir`, `ModTime`, ...) plus `modified` (`fileManager.convertRcloneFilesToMotuz` maps them). **`modified` is always UTC: ISO 8601 with `Z` and whole seconds (`2026-09-27T04:57:00Z`), or null** (`utils/file_times.py`). Local times come from epoch seconds, so the server's `TZ` never matters; rclone's `ModTime` (any offset) is converted to UTC; placeholder times before 1971 (Go's zero time) become null. Never return naive local times. The panes compute the age ("5 min ago") from that instant against `Date.now()` (`utils/fileAge.js`, re-rendered every 30 s without refetching) and show the exact time in the browser's time zone, with the zone's name, as the tooltip.
- **Read-only viewer, a pager like `less`** (double-click on a file in a pane opens `FileViewerDialog.jsx`, which renders text, never HTML). `POST /api/system/files/view/chunk/ {connection_id, path, offset | before | from_end, length, follow}` → `{path, content, offset, end, size, bof, eof, encoding}` (`offset`/`end`: the byte range the content covers). `length` defaults to and is capped at 256 KiB (`utils/file_view.py`: `CHUNK_BYTES`; min 256); `offset` reads forward, `before` reads the chunk that ends there (the previous one), `from_end` the tail; only one of them, ints (not bools) validated in `parse_chunk_request` (400; an offset past the end is 400 too). A forward read at `offset == size` returns empty content with `eof` and reads nothing (the local reader skips both reads when the start is at the end; for cloud files `lsjson --stat` is the only rclone call). `follow: true` (only with `offset`; `ChunkRequest.follow`) is the viewer's follow mode: an incomplete last line is withheld until its newline arrives (`align_complete_lines`; `eof` is then true with `end < size`), an offset past the end returns no content and the new, smaller `size` instead of 400 (the viewer reloads the tail), and a cloud read past offset 0 skips the second `rclone cat --count 8192` (`skips_text_check`: the text check ran when the file was opened; the tail reload after a truncation checks again). Chunks hold whole lines (`align_forward` / `align_backward`, pure functions): forward reads end after the last `\n` unless at EOF, backward reads start after the first `\n` unless at BOF (reading one byte before the range, so a chunk that starts at a line keeps it); a line longer than a chunk is split, never inside a UTF-8 character. Text or binary is decided on the file's first 8 KiB (`HEAD_CHECK_BYTES`, `decode_text`) for every chunk, so the tail of a binary file is also 415; chunks decode with U+FFFD replacements. The older `POST /api/system/files/view/` (first 1 MiB, `{path, content, truncated, size, encoding}`) is kept. Local files are read as the user by `_VIEW_READER` (`sudo -n -u <user> -- env python3 -I -S -c`, absolute paths only, stat + fstat: regular files only, so devices and FIFOs are never read, non-blocking open, `pread` of the first bytes and of the range, a negative start counts from the end, returns size and start, so a tail is one process; timeout, process group killed on timeout); cloud files with `rclone lsjson --stat` (size; a folder is refused: `rclone cat` of a folder would print every file in it; bucket storage reports a missing path as a virtual folder, hence "is a folder or does not exist"), `rclone cat --offset --count` and, unless the range starts at 0, `rclone cat --count 8192` for the text check, as the user with `_formatCredentials`; the connection goes through `cloud_connection_manager.retrieve` (404 for other users'). Errors: 403 cannot read, 404 missing, 415 not text, 400 folder / not a regular file / relative path / bad offset or length, 504 timeout. Never log file contents. The dialog keeps the chunks itself (`utils/viewerChunks.js`, contiguous window of at most `MAX_CHUNKS` = 16 chunks = 4 MiB of text, chunks dropped at the far end and fetched again), loads the next/previous chunk when the viewport is within two screens of the loaded part's bottom/top, keeps the top visible chunk in place when chunks are added or dropped above (`getSnapshotBeforeUpdate`, `overflow-anchor: none`), focuses the scroll container (PageUp/PageDown, arrows, Space, Home/End of the loaded part), and has "Jump to top" / "Jump to bottom" (Ctrl+Home / Ctrl+End), which replace the window with the first chunk or the tail. **Follow** (button next to them, or `F`, like `less +F` / `tail -f`) goes to the end and polls `{offset: followEnd, follow: true}` (`utils/viewerFollow.js`, pure functions with node tests): 2 s for local files, 10 s for cloud connections, ×1.5 per poll without news up to 30 s, reset by new data; `setTimeout` after each answer, and every read of the dialog goes through one promise queue (`request()`), so no two requests overlap. New lines are merged into the last chunk while it stays ≤ 256 KiB (`appendFollowChunk`, so polls do not use up `MAX_CHUNKS`) and scrolled into view; the toolbar shows "Following… (updated 3 s ago)". Scrolling up by more than 16 px (wheel, PageUp/Home/↑, Jump to top) pauses the auto-scroll; lines are still appended (old chunks dropped at the top, the visible chunk kept in place) or, when the window no longer reaches the end, only counted: "Paused: N new lines below · Resume"; Resume or scrolling back to the bottom continues. `size < followEnd` → notice "File was truncated, showing the new end" and the tail is reloaded; 404 → notice, follow stops; 400/403/415 stop it too, other errors back off. More than 4 MiB new at once loads the tail instead. Polling stops when the dialog closes (unmount), while `document.hidden` (one poll at once on `visibilitychange` back), and after an hour without activity (keys, mouse, wheel) with a notice. Not detected: a file replaced by a different one that is already at least as long as what the viewer has.
- **Image and Markdown viewer.** Double-click dispatches by extension (`utils/viewerKind.js`, case-insensitive, node tests; `Dialogs.jsx` picks the dialog): `.png .jpg .jpeg .gif .webp` → `ImageViewerDialog.jsx`, `.md .markdown` → `MarkdownViewerDialog.jsx`, everything else (SVG too) → the pager. `POST /api/system/files/view/image/ {connection_id, path}` (`utils/image_view.py`) returns the raw bytes: the type from the magic number only (`detect_type`: PNG, JPEG, GIF, WebP; never the name or rclone's `MimeType`), anything else 415 (`NotAnImageError`, SVG with its own message: SVG can carry script), 413 above `VIEW_IMAGE_MAX_BYTES` (`MOTUZ_VIEW_IMAGE_MAX_BYTES`, default 25M, 1K..256M, parsed in `config.py` at import like the rclone settings; `&viewer-environment`, app only; the e2e stack uses 2M). Local: the same `_VIEW_READER` with a `max_size` argument (refused on fstat before reading anything, `{"error": "large", "size"}`), reading at most cap+1 bytes; cloud: `lsjson --stat` (413 before any `cat`) then `rclone cat --count cap+1`; both re-check what was read (the file may have grown). Headers (`response_headers`): the detected type, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, `Cache-Control: no-store`, `Cross-Origin-Resource-Policy: same-origin`, `Content-Disposition: inline` with a sanitized ASCII name plus `filename*` (`safe_filename`). Same permission model and errors as the pager (403/404/400/504, other users' connections 404). The frontend fetches with the Bearer token (`apiActions.viewImage`, RSAA whose success payload is `{blob, type, size}`), never puts a token in a URL, shows a `blob:` URL created with the detected type and revokes it on unmount; fit to window by default, click / button / `Z` toggles 100%. Markdown: up to `MARKDOWN_MAX_BYTES` (1 MiB) read with the chunk endpoint (notice + "Show the whole file as text" if larger), rendered by `MarkdownContent.jsx` (react-markdown 10 + remark-gfm, a lazy `import()` chunk of ~160 KB, never in the main bundle). No `rehype-raw`: raw HTML becomes text. `urlTransform`: `href` only http/https/mailto (`safeLinkUrl`, new tab, `rel="noopener noreferrer"`) or in-document `#fragments` (footnotes, scrolled in the container); other links render as `.md-link-disabled` text. Images: remote, protocol-relative and `data:` are never fetched (alt + "remote image not loaded"); relative/absolute paths are resolved against the file's folder (`markdownImageSource`) and, if PNG/JPEG/GIF/WebP by extension, loaded through the image endpoint on the same connection (at most 50, 2 at a time, blob URLs revoked on close). "Rendered | Source" (`ViewerModeSwitch`, `setFileViewerMode` → `fileViewerDialogData.mode`) swaps to the pager (with follow) and back without the modal animation.

### Credentials from the user's home directory
`utils/local_credentials.py`. The New Connection dialog (`LocalCredentialPicker.jsx`) calls `GET /api/connections/local-credentials/?type=s3|azureblob`, which lists AWS profiles (`~/.aws/credentials`, `~/.aws/config`, SSO login state from `~/.aws/sso/cache`) s3/azureblob remotes in `~/.config/rclone/rclone.conf` (or `~/.rclone.conf`), and Azure CLI logins (one per tenant, from `~/.azure/azureProfile.json`). It returns metadata only (name, kind, region, key id masked to the last 4, Azure account, `usable`/`reason`). A connection created from one has `subtype='profile'` plus `profile_source` (`aws`/`rclone`/`azure-cli`) and `profile_name` (the tenant id for `azure-cli`, which also keeps the non-secret `azure_account`: a login is not a storage account), and no stored credentials. `_formatCredentials` calls `local_credentials.resolve()`, which re-reads the files every time rclone runs (rotated keys are picked up).
- Files are read only as the user: `sudo -n -u <user> -- env python3 -I -S -c <reader>` with fixed relative paths below `_homepath_with_impersonation`, non-blocking open, regular files only, 1 MiB cap, timeout. Never read them as root.
- rclone never gets the user's AWS files: static keys, session tokens and roles (`role_arn` + a `source_profile` with keys, via rclone's `role_arn`) are passed as `RCLONE_CONFIG_*` values. With the raw files (env_auth) the AWS SDK would run `credential_process`, i.e. users could run programs in the containers. SSO profiles use env_auth with a config file Motuz writes from allowlisted SSO keys (`/tmp/motuz-aws-config/<sha256>.ini`, no secrets) and `HOME` set to the user's home, because `sudo -E` keeps root's `HOME`. `credential_process`, MFA roles, `credential_source`, rclone `env_auth`/`use_msi` are reported as unusable.
- Azure CLI logins (and rclone remotes with `use_az`) need `az` in the image: build arg `INSTALL_AZURE_CLI=true` (`MOTUZ_INSTALL_AZURE_CLI` in `.env`, off by default, +590 MB); otherwise they are listed as unusable. rclone runs `az account get-access-token` as the user with `azure_cli_env()`: `HOME`/`AZURE_CONFIG_DIR` at the user's `~/.azure` (az refreshes its token cache there, as the user), az extensions and dynamic installs off (they are Python code from `~/.azure`), managed identity pointed at a closed port and managed-identity logins refused (they would be the server's identity). The az launcher runs Python with `-I`, so `~/.local` site-packages are ignored. Never run `az` as root with a user's `~/.azure`.

### Jobs (copy + integrity check)
1. The manager inserts a `CopyJob`/`HashsumJob` row, picks a pool (`job_routing.choose_pool`; remote pools are queued for workers, see "Remote workers") and, for `central`, dispatches the Celery task (`tasks/celery_tasks.py`) with the **Celery task id `copy-<id>` / `hashsum-<id>`** (`_celery_task_id`; the two job types have separate id sequences, so a bare id would let revoking copy job N discard hashsum job N). `_async_result` falls back to the bare id for jobs created before the prefix existed.
2. The worker starts rclone (`copyto` or `md5sum`) in its own process group, with background threads from `utils/copy_job_queue.py` / `utils/hashsum_job_queue.py` reading stdout (the `--progress` stats in non-TTY form, where the bytes and file-count lines are both named `Transferred:`) and stderr. The polling loops (`watch_copy`, `run_hashsum`) are in `utils/job_runner.py`, shared with the remote worker agent.
3. Once per second the task writes progress to the DB row and to the Celery task state `meta` (text/error text via RabbitMQ result backend).
4. `retrieve` merges `AsyncResult(id).info` into the DB object for live text; this needs a shared result backend (`CELERY_RESULT_BACKEND = 'db+' + database URI`), since Celery 5 removed the `amqp` backend. `stop` calls `revoke(terminate=True)`; the task's SIGTERM handler (`_terminate_rclone_on_sigterm`) kills the rclone process group before the worker process exits. Email notifications go through `utils/email_utils.py`.

Hashsum jobs run md5sum on src then dst, build file trees (`utils/file_utils.py`), and store only the differing branches (`remove_identical_branches`) as JSON.

**rclone performance** (`utils/rclone_tuning.py`, README "Performance tuning"; stdlib only). Installation defaults `MOTUZ_RCLONE_{TRANSFERS,CHECKERS,MULTI_THREAD_STREAMS,MULTI_THREAD_CUTOFF,BUFFER_SIZE,S3_UPLOAD_CONCURRENCY,S3_CHUNK_SIZE,AZUREBLOB_UPLOAD_CONCURRENCY,AZUREBLOB_CHUNK_SIZE}` (unset/empty = rclone's default = no flag, so the command line is unchanged), caps `MOTUZ_RCLONE_MAX_{TRANSFERS,CHECKERS,MULTI_THREAD_STREAMS,UPLOAD_CONCURRENCY}` (64/128/32/64), `MOTUZ_RCLONE_MEMORY_BUDGET` (8G) and `MOTUZ_RCLONE_EXTRA_FLAGS` (only the flags in `EXTRA_FLAGS`, each with a validated value; no free-form flags); passed to app and celery via the `&rclone-environment` anchor in `docker-compose.yml`. `config.py` calls `rclone_tuning.settings()` at import, so an invalid value stops the app and the worker with a `TuningConfigError` naming the variable. Jobs store validated overrides in `copy_job.performance` / `hashsum_job.performance` (JSON; hashsum only `checkers`); names outside `PER_JOB` (e.g. `buffer_size`), non-integer / non-size values, values above a cap and combinations whose `estimate_memory` (`transfers × (max(1, streams) × buffer + max(upload_concurrency, streams) × chunk)`, chunk term for S3/Azure destinations only) exceeds the budget are a 400; settings for another backend than the destination's are dropped. `copy_flags` / `hashsum_flags` re-validate stored values against the current caps and emit one argv item per flag (`--transfers=32`) formatted from parsed numbers, inserted before `copyto` / `md5sum`; never build these flags from user text. `GET /api/copy-jobs/performance/?dst_cloud_id=` (`describe`) returns the fields for the destination's type, limits, defaults, `buffer_size`, the budget and the presets (`PRESETS`: Default, Many small files, Few large files, Maximum, clamped to the caps and reduced by `fit_preset` until they fit the budget). Frontend: `CopyJobPerformance.jsx` (collapsed section in `NewCopyJobDialog`), helpers with node tests in `utils/copyPerformance.js` (validation, the same estimate, preset matching); `createCopyJob` keeps the dialog open on failure and the dialog shows the error (`CREATE_COPY_JOB_FAILURE` is not in `alertReducer`); `EditCopyJobDialog` shows the settings, Retry keeps them, Check Integrity passes `checkers`. The e2e stack sets `MOTUZ_RCLONE_CHECKERS=16` and `MOTUZ_RCLONE_MAX_TRANSFERS=48` (`test/e2e/compose.yml`).

### Remote workers (HTTPS only)
Jobs can run on remote workers that reach the central node only by outbound HTTPS (optionally via an HTTP proxy); no database access, no inbound ports. README "Remote workers (HTTPS only)" is the operator documentation.
- **Routing** (`managers/job_routing.py`, called by the copy/hashsum managers' `create`): a job with a local path goes to `LOCAL_JOB_POOL`, a cloud-to-cloud job whose source is large (`estimate_size`: `RcloneConnection.size` = `rclone size --json` with `JOB_SIZE_TIMEOUT`, a timeout counts as large; the phase-4 hook) to `LARGE_JOB_POOL`, the rest to `central`. Defaults (`MOTUZ_LOCAL_JOB_POOL` / `MOTUZ_LARGE_JOB_POOL` unset) are `central` = Celery as before. Any other pool gets a `remote_job` row (`models/worker.py`, migration `d9e2f4a6b8c1`) instead of a Celery task. `job_routing.rclone_flags(job_type, job)` puts the job's performance flags (`rclone_tuning.copy_flags` / `hashsum_flags`, computed on the central node where the `MOTUZ_RCLONE_*` settings are) into the ticket; the worker passes them unchanged as `extra_flags` (checked to be `--` options), at the same place in the command line as `copy`/`md5sum` do.
- **Auth** (`managers/worker_manager.py`): `worker` rows (`manage.py workers add|list|revoke|bootstrap`, click group in `manage.py`) hold SHA-256 hashes of `mzw1.<id>.<random>` secrets; `worker_bootstrap_token` single-use `mzb1.` tokens create an ephemeral worker (optionally `bound_job` `copy:<id>`/`hashsum:<id>`, revoked when that job ends). Worker access tokens are PyJWT HS256 with a key derived from `SECRET_KEY` (HMAC, never `JWT_SECRET_KEY`), `aud=motuz-worker`, `typ=worker`, `pool`; `authenticate()` also checks the row is not revoked. So user endpoints (`flask_jwt_extended`) never accept worker tokens and `/api/workers` never accepts user tokens. All secret comparisons go through `_hash_matches` (`hmac.compare_digest`).
- **API** (`views/worker_views.py`, a plain Blueprint at `/api/workers`, not flask-restx/Swagger): `auth`, `auth/refresh`, `claim` (long poll up to 25 s, 204 if nothing), `jobs/<remote_job id>/progress` and `/finish` (worker token + `X-Motuz-Ticket`), `oauth/token`. In-memory rate limits (`utils/rate_limit.py`; one uWSGI process). Audit lines go to the `motuz.audit` logger, never with secrets.
- **Claim**: `SELECT ... FOR UPDATE SKIP LOCKED` then an `UPDATE ... WHERE state='QUEUED'` compare-and-set (atomic on SQLite too); `QUEUED -> RUNNING -> DONE`. The ticket (`build_ticket`) has the job (type, id, owner, options, src/dst with path, `local`, and for connections `rclone_env` from `_formatCredentials` or, for `subtype='profile'`, `profile_connection` (non-secret fields, resolved on the worker as the owner)), `rclone_flags`, `ticket_token` `mzt1.<remote_job id>.<random>`, expiry, lease. Hashsum tickets name both sides' remote `src` (md5sum reads `src`). Stored: hashes only; the ticket hash stays after DONE so late calls get 410.
- **Lease**: `WORKER_LEASE_SECONDS` (120), renewed by progress; `expire_leases()` (claims, and user list/retrieve, throttled to every 5 s) marks expired jobs FAILED with the reason in `progress_error` (never requeued); `revoke_worker` fails the worker's running jobs at once. Stop: `request_stop` drops a queued job or sets `stop_requested`, returned as `action: stop` by the next progress call. `retrieve` takes live text from `remote_job.progress_text/error_text` (`apply_remote_progress`) instead of Celery. `finish` sets the final state (STOPPED stays STOPPED), hashsum trees, and sends the emails.
- **HTTPS token broker**: for brokered connections the ticket's token has refresh token `mzr1.<remote_job id>.<side>.<random>` (not the handle) and `token_url` `MOTUZ_PUBLIC_URL` or the request's host + `/api/workers/oauth/token` (`_formatCredentials(..., token_broker=fn)` -> `broker_token(via=fn)`). `handle_worker_token_request` checks the broker hash, job RUNNING, lease, worker not revoked, and that the side's connection is brokered and the owner's, locks it and calls `token_broker_manager.serve_locked_connection` (the loopback broker's code after its handle lookup). rclone gets this narrower token, not the ticket, because the job's owner can read rclone's environment.
- **Agent** (`src/worker/motuz_worker.py`, stdlib only, imports `api.utils.*` and `api.version` from `src/backend`: `api/__init__.py` loads the Flask app lazily (PEP 562 `__getattr__`), so `api.utils` must never import the application or config): sign in, `check_host` (required mounts, rclone), version check against `api/version.py` (`VERSION`, `WORKER_PROTOCOL`; bump them when the job code or worker API changes), claim, then `RcloneConnection.copy_with_credentials` / `md5sum_with_credentials` (same command builders as `copy`/`md5sum`; `extra_env` adds the proxy variables and `SSL_CERT_FILE`, which `user_process_env` would otherwise drop) and `utils/job_runner.py` (`watch_copy`, `run_hashsum`, `exit_state`, shared with `tasks/celery_tasks.py`). Unit `src/worker/motuz-worker.service` (systemd --user of the `motuz` account, exit 78 = no restart), `src/worker/worker.env.example`; the app image contains `/app/src/worker`.

### OAuth token broker (OneDrive, Google Drive)
rclone gets OAuth tokens via env vars and `--config=/dev/null`, so it can never persist a refreshed token. For brokered types (`token_broker_manager.BROKERED_TYPES`: `onedrive`, `drive`, derived from the provider definitions in `oauth_manager.PROVIDERS`) `_formatCredentials` passes the current access token plus an opaque per-connection handle (`cloud_connection.token_broker_handle`) as the refresh token, and sets the remote's `token_url` to `TOKEN_BROKER_URL`. That is `/internal/oauth/token`, served on uWSGI's loopback `http-socket` 127.0.0.1:5001. It is exposed nowhere else: Traefik's router rule excludes `/internal`, and `internal_views.only_on_broker_socket` returns 404 unless `SERVER_PORT` (the accepting socket's port, not the Host header) is the port of `TOKEN_BROKER_URL`, i.e. 5001 in production and 5000 with the dev server. The broker locks the connection row, returns the cached access token if it has more than 5 minutes left, and otherwise refreshes upstream with the real refresh token, which never leaves the server. Concurrent jobs share a single refresh. A response without `refresh_token` (Google) keeps the stored one; a new one (Microsoft rotates) replaces it. Test it against a fake token endpoint by setting `MOTUZ_ONEDRIVE_TOKEN_URL` / `MOTUZ_GDRIVE_TOKEN_URL`.

Providers: `oauth_manager.Provider` holds everything provider specific (config prefix `ONEDRIVE`/`GDRIVE` for `*_CLIENT_ID/_CLIENT_SECRET/_REDIRECT_URI/_AUTH_URL/_TOKEN_URL`, rclone's public app id + obscured secret + loopback redirect, scopes, extra auth params, drive discovery, connection columns, token and client-id columns). Routes are `/api/oauth/<provider>/{start,finish,callback,flows/<state>,connect}` with provider `onedrive` or `gdrive`; OneDrive's callback lands on `/clouds?oauth_state=...`, others add `&oauth_provider=<name>`. Google Drive (connection type `drive`, columns `gdrive_*`) uses `access_type=offline&prompt=consent` (else Google returns no refresh token) and discovers My Drive (`about`) plus shared drives (`drives`, which set rclone's `team_drive`). rclone's shared Drive client is heavily rate limited and being retired by rclone during 2026; the README ("Google Drive") describes the own client and Google's restricted-scope limits. Frontend: `OauthSignIn.jsx` is the one sign-in component for both providers (texts in `OAUTH_PROVIDERS`); `GdriveSection.jsx` holds the Drive fields for a pasted rclone token. The flow result includes the signed-in `account` (`discover(access_token, info)` sets `info['account']`; stored with the drives in `oauth_flow.drives`).

### New Cloud Connection dialog
Keep it unambiguous: top to bottom Type, the only "Connection Name" field, the type's own part (sign-in, "Credentials" found in the home directory, or credentials), then advanced options collapsed; exactly one primary button, "Create connection", in the footer. For OneDrive/Google Drive (`CloudConnectionDialogFields` reports the sign-in provider through `onModeChange`) the footer has only Cancel and "Create connection", disabled with "Sign in first" until `OauthSignIn` reports a chosen drive (`onOauthChange`); the dialog then calls `/api/oauth/<provider>/connect/` with the Connection Name, which the sign-in prefills from the drive until the user types one. The sign-in part has no name field and no create button. Other types and "Advanced: paste a token" get "Test connection" + "Create connection". All errors (sign-in, connect, create/save via `state.api.cloudErrorMessage`, failed tests) appear once, in `DialogError` above the footer buttons. A callback (`/clouds?oauth_state=...` or `?oauth_error=...`, plus `&oauth_provider=` except for OneDrive) opens the dialog on the provider's type; the dialog reads it once in its constructor. The UI suites check this layout.

"Sign in with Microsoft/Google" (`oauth_manager`) uses rclone's public app, or an own app when `MOTUZ_ONEDRIVE_CLIENT_ID` / `MOTUZ_GDRIVE_CLIENT_ID` is set (secrets: docker secrets `MOTUZ_ONEDRIVE_CLIENT_SECRET` / `MOTUZ_GDRIVE_CLIENT_SECRET`, empty files by default; empty means unset). A refresh token only works with the app that issued it, so connections remember it in the server-controlled `cloud_connection.onedrive_client_id` / `gdrive_client_id` (NULL = rclone's app, e.g. pasted tokens; pasting a token resets it, `cloud_connection_manager._TOKEN_CLIENT_COLUMNS`). The broker's `connection_client_credentials` / `upstream_client_credentials` forwards rclone's own client credentials for rclone-app connections, substitutes the own app's id and secret (never given to rclone) for own-app connections, and refuses others with `invalid_grant`. Commands run as a user (rclone, via `sudo -E`) get only an allowlisted environment, `abstract_connection.user_process_env`: `PATH`/`LANG`/`LC_ALL`/`TZ` plus the explicit `RCLONE_CONFIG_*` values, never the server's secrets or any other `MOTUZ_*` variable, because the user can read their own process's environment (`/proc/<pid>/environ`).

### Adding a field to a cloud connection type
Follow the pattern of the `kms_encryption_key_arn` commits (`8a8988f`, `0a02274`):
1. Add a column in `models/cloud_connection.py` and an Alembic migration.
2. Add it to the DTO in `views/cloud_connection_views.py` (use `PrivateString` for secrets).
3. Map it to an rclone env var in `RcloneConnection._formatCredentials`, and add its suffix to the logging allowlist if it is safe to log.
4. Add the form field in `src/frontend/js/views/Dialogs/CloudConnection/CloudConnectionDialogFields.jsx`.

### Frontend (`src/frontend/js/`)
Webpack `resolve.modules` includes `src/frontend/js`, so imports are root-relative (`'reducers/reducers.jsx'`, `'actions/apiActions.jsx'`). API calls are `RSAA` actions (redux-api-middleware) in `actions/apiActions.jsx` with `withAuth` headers. `middleware/authMiddleware.jsx` handles token refresh. `redux-persist` keeps auth/settings in local storage. The main UI is a two-pane file browser (`views/App/Pane/`) with command bars and the job tables in `views/App/CopyJobSection/`. Each pane has Name / Age / Size columns with sortable headers. Selection, copy (arrow button, `dialogActions.buildCopyJobData`) and drag and drop work with row indexes, so `state.pane.files[side]` is always kept in the displayed (sorted) order: listings are sorted in `paneReducer` with `utils/fileSort.js` (`..` first, folders before files, names case-insensitive and natural), and a header click (`SORT_CHANGE`) re-sorts the array and moves the selection with it (`resortWithSelection`). The sort of each pane is persisted in `settings.paneSort` and copied to `state.pane.sort` on `REHYDRATE`.

### Deployment
All services in `docker-compose.yml` use `network_mode: host`:
- **traefik** (`traefik:v3.7`, container `motuz_traefik`): the only thing listening beyond loopback (:80 redirects to :443). File provider only, no docker socket, no dashboard/API. Static config is the service's `command` flags (Traefik takes static config from exactly one source, and flags let compose substitute `MOTUZ_ACME_*` from `.env`); dynamic config is `deployment/docker/traefik/dynamic/motuz.yml`, a Go template: one router for everything except `/internal`, security-headers middleware, `responseHeaderTimeout: 600s` and no connection reuse to uWSGI, TLS 1.2+ with AEAD ciphers. TLS: `$MOTUZ_DOCKER_ROOT/certs/cert.{crt,key}` by default (reloaded only on `docker restart motuz_traefik`), or Let's Encrypt HTTP-01 when `MOTUZ_ACME_DOMAIN` is set (`acme.json` in `$MOTUZ_DOCKER_ROOT/traefik`).
- **app** (`PYTHON_ENVIRONMENT=prod`): uWSGI `http-socket`s on `127.0.0.1:5000` (for Traefik) and `127.0.0.1:5001` (token broker), `src/backend/wsgi.ini`. Besides the API it serves the built frontend (`views/frontend_views.py`, via `wsgi.file_wrapper`/sendfile): `/js`, `/css` cached 30 days, `/img` 7 days, `/about` (public homepage for OAuth reviewers), `/privacy` and `/terms` are server-rendered public pages (`views/legal_views.py`, templates in `api/templates/legal/`, operator from `MOTUZ_OPERATOR_NAME` / `MOTUZ_CONTACT_EMAIL` / `MOTUZ_OPERATOR_URL`; required for Google's OAuth consent-screen branding), anything else not under `/api`, `/swaggerui`, `/internal` gets `index.html` with `no-store` (SPA routes). Traefik only terminates TLS and routes because it cannot serve files, and this uWSGI build has no PCRE, so `static-map` could not set per-path Cache-Control. `wsgi.py` wraps the app in `ProxyFix(x_for=1, x_proto=1)` only (never host/port, see the broker check).
- **celery** (image built `FROM fredhutch/motuz_app`, so rebuild app first), **rabbitmq**, **database** (postgres).

Secrets are files in `$MOTUZ_DOCKER_ROOT/secrets` (default `/docker`), exposed as docker secrets and exported to env by `deployment/docker/load-secrets.sh`. Compose refuses to start when a secret file is missing, so optional secrets are created as empty files by `bin/_utils/optional_secrets.sh` (run by `bin/prod/start.sh` and `bin/quickstart.sh`). The rclone version and its SHA256 are pinned in `deployment/docker/app/Dockerfile`. PostgreSQL is 18 (`PGDATA` is set to `/var/lib/postgresql/data` because the 18 images changed the default). When the `database` image major version is bumped, `bin/_utils/upgrade_postgres.sh` (run by `bin/prod/start.sh` and `bin/dev/database_start.sh`) migrates `$MOTUZ_DOCKER_ROOT/volumes/postgres` with dump/restore, verifies row counts and keeps the old directory as `postgres.pg<old>.<timestamp>`. The database must be owned by `motuz_user` (PostgreSQL 15+ public schema rules). The app runs `manage.py db upgrade` on each start. `bin/prod/start.sh` runs `docker-compose down --remove-orphans`, which also removes the `motuz_nginx` container of pre-Traefik installs (README, "Migrating from nginx to Traefik"). `.gitlab-ci.yml` is a placeholder; CI runs on GitHub Actions (see Commands).
