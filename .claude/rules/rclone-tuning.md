# Jobs: rclone performance tuning

Detail for rclone performance settings and per-job overrides.

**rclone performance** (`utils/rclone_tuning.py`, README "Performance tuning"; stdlib only). Installation defaults `MOTUZ_RCLONE_{TRANSFERS,CHECKERS,MULTI_THREAD_STREAMS,MULTI_THREAD_CUTOFF,BUFFER_SIZE,S3_UPLOAD_CONCURRENCY,S3_CHUNK_SIZE,AZUREBLOB_UPLOAD_CONCURRENCY,AZUREBLOB_CHUNK_SIZE}` (unset/empty = `MOTUZ_DEFAULTS` for transfers/checkers, 16/32, lowered to the caps and dropped by `_add_motuz_defaults` if they would exceed the memory budget; rclone's default = no flag for the rest, except buffer size: `copy_flags(..., src_local=True)` adds `--buffer-size=0B` (`LOCAL_SOURCE_BUFFER_SIZE`) for jobs from a local source, from `RcloneConnection.copy` and `job_routing.rclone_flags`), caps `MOTUZ_RCLONE_MAX_{TRANSFERS,CHECKERS,MULTI_THREAD_STREAMS,UPLOAD_CONCURRENCY}` (64/128/32/64), `MOTUZ_RCLONE_MEMORY_BUDGET` (8G) and `MOTUZ_RCLONE_EXTRA_FLAGS` (only the flags in `EXTRA_FLAGS`, each with a validated value; no free-form flags); passed to app and celery via the `&rclone-environment` anchor in `docker-compose.yml`. `config.py` calls `rclone_tuning.settings()` at import, so an invalid value stops the app and the worker with a `TuningConfigError` naming the variable. Jobs store validated overrides in `copy_job.performance` / `hashsum_job.performance` (JSON; hashsum only `checkers`); names outside `PER_JOB` (e.g. `buffer_size`), non-integer / non-size values, values above a cap and combinations whose `estimate_memory` (`transfers × (max(1, streams) × buffer + max(upload_concurrency, streams) × chunk)`, chunk term for S3/Azure destinations only) exceeds the budget are a 400; settings for another backend than the destination's are dropped. `copy_flags` / `hashsum_flags` re-validate stored values against the current caps and emit one argv item per flag (`--transfers=32`) formatted from parsed numbers, inserted before `copyto` / `md5sum`; never build these flags from user text. `GET /api/copy-jobs/performance/?dst_cloud_id=` (`describe`) returns the fields for the destination's type, limits, defaults, `buffer_size`, the budget and the presets (`PRESETS`: Default, Many small files, Few large files, Maximum, clamped to the caps and reduced by `fit_preset` until they fit the budget). Frontend: `CopyJobPerformance.jsx` (collapsed section in `NewCopyJobDialog`), helpers with node tests in `utils/copyPerformance.js` (validation, the same estimate, preset matching); `createCopyJob` keeps the dialog open on failure and the dialog shows the error (`CREATE_COPY_JOB_FAILURE` is not in `alertReducer`); `EditCopyJobDialog` shows the settings, Retry keeps them, Check Integrity passes `checkers`. The e2e stack sets `MOTUZ_RCLONE_CHECKERS=16` and `MOTUZ_RCLONE_MAX_TRANSFERS=48` (`test/e2e/compose.yml`).

**S3 integrity and CPU (measured 2026-10-17, AWS us-west-2, 100 MB files):** Motuz passes `--s3-disable-checksum`, so multipart uploads (files >= `--s3-upload-cutoff`, rclone default 200 MiB) get no stored MD5: rclone's post-copy check logs `Dst hash empty - aborting Src hash check`, and Check Integrity (`rclone md5sum` on S3) sees empty hashes for those objects. Single PUTs are checked (ETag = MD5). Every request still carries `Content-MD5` (per part for multipart) and the SDK's CRC32, which S3 verifies (`BadDigest`). About two thirds of rclone's upload CPU is MD5 (single PUTs hash each file twice: a pre-read for `Content-MD5`, then during the transfer); TLS is about 5%. Multipart from 32M with `--ignore-checksum` doubled throughput (1.1 -> 2.1 GB/s on 8 vCPUs); `--ignore-checksum` is global in rclone and not in `EXTRA_FLAGS`, and only safe for S3 destinations that verify `Content-MD5` (AWS, Ceph RGW, MinIO), never for local/Azure/SFTP/Drive destinations.

**Per-connection S3 options** (migration `a3c5e7f9b2d4`, `cloud_connection_manager._apply_s3_rules`): `s3_provider` (rclone's provider, validated against `s3_providers.PROVIDER_VALUES`; NULL/legacy: AWS without endpoint, else Other; a profile connection keeps an rclone remote's own provider), `s3_chunked` -> per-remote `RCLONE_CONFIG_<R>_UPLOAD_CUTOFF` `32Mi` or `5Gi` (a global `--s3-upload-cutoff` in `MOTUZ_RCLONE_EXTRA_FLAGS` overrides it), `s3_skip_checks` (AWS/Ceph only) -> `rclone_connection.destination_checks(dst)`: `--ignore-checksum` and, for `all`, `AWS_REQUEST_CHECKSUM_CALCULATION=when_required`, only for copy jobs and only from the destination. `crc32c` (AWS only, `s3_providers.CRC32C_PROVIDERS`; a 400 for other providers, the dialog offers it only for Amazon S3) adds `RCLONE_S3_PART_CHECKSUM=crc32c`, `all` adds `RCLONE_S3_PART_CHECKSUM=none`. Remote workers get them as `rclone_flags` and the ticket's `rclone_job_env` (accepted by `checked_job_env` only from `JOB_ENV_VALUES`; `WORKER_PROTOCOL` 3).

**Local to local** (both sides local paths): `copy_with_credentials` adds `RCLONE_LOCAL_HASHES=sha256` (`LOCAL_TO_LOCAL_ENV`; rclone checks a copy with the first common hash, MD5, otherwise) and integrity checks run `rclone hashsum sha256` (`job_runner.hashsum_type`, decided on the central node and on the worker from the two sides; `hashsum_job_queue` parses 32- and 64-character hashes). Measured 3 GB local -> local, 16 transfers: MD5 1.68 s / 7.8 user-s, SHA-256 1.07 s / 3.5, no check 0.99 s / 0.1.

**md5-simd and part checksums** come from the rclone branch `s3-md5-simd` of github.com/dirkpetersen/rclone (`--md5-simd`, `--md5-simd-servers`, `--s3-part-checksum md5|crc32c|none`). Motuz passes them only as rclone variables (`rclone_tuning.md5_env`: `RCLONE_MD5_SIMD=true`, `RCLONE_MD5_SIMD_SERVERS` from `MOTUZ_RCLONE_MD5_SIMD_SERVERS`, default 2, 0 = none; `RCLONE_S3_PART_CHECKSUM` from `destination_checks`), never as flags: a stock rclone ignores unknown variables but fails on unknown flags, so Motuz works with either binary. `md5_env` goes into copy and md5sum jobs (also hashsum tickets). Since v1.76.0-md5simd.3 (the pinned release) rclone ignores `--md5-simd` on CPUs without AVX2 (arm64 such as Graviton, older x86) and uses crypto/md5, so the default of 2 servers is harmless there. Measured (8 vCPUs, AWS, 33 GB, 32 transfers, concurrency 16, rclone v1.76.0-md5simd.2 where the SDK computes CRC32C as a trailer while sending): crypto/md5 2.6 GB/s, md5-simd 3.1, CRC32C 3.8, CRC32C with `--buffer-size=0` 4.2-4.5 (machine saturated: kernel sends, page-cache reads, softirq, TLS). Things that did not help: coalescing TLS records into large writes, cubic instead of BBR, GOAMD64=v4, GOGC=400, more transfers, larger parts, computing the MD5 while filling each part.

**Overwrite policy** (README "Overwriting existing files"; migration `c8e1a3f5d7b9`). `motuz_destination` (unique `storage_key, path`, the lookup index; `owner` only records who wrote it first, never filtered: shared on purpose) holds the items Motuz wrote: `copy_job_manager.create` and `upload_manager.create` call `overwrite_policy.decide` first, then `register` (same transaction, `ON CONFLICT DO NOTHING`, skips '/', unknown storages and covered paths) the copy's `dst_resource_path` / each upload top-level item. `is_motuz_destination` = `path IN ancestors(path)` (segment match, one indexed query). `motuz_destinations` (stdlib, imported by `config.py`): `allow_general_overwrites()` (`MOTUZ_ALLOW_GENERAL_OVERWRITES`, true/false, else `OverwriteConfigError` at import), `storage_key` (owner-independent: `local:`, `s3:aws[-cn|-us-gov]` or `s3:<endpoint>`, `azureblob:<account or SAS URL without query>`, `swift:`, `gcs:`, `sftp:host:port`, `onedrive:<drive id>`, `drive:<team>|<root folder>`, `webdav:<url>`; None = unknown = never overwrite: Dropbox, profiles whose endpoint/account come from the user's home), `normalized_path` (refuses `.`/`..` segments and relative local paths). `copy_job.overwrite` False -> `rclone_tuning.copy_flags(..., overwrite=False)` appends `KEEP_EXISTING_FLAGS` = `--ignore-existing --combined=-` (also in tickets via `job_routing.rclone_flags`; NULL = older jobs = overwrite). rclone logs kept files only at DEBUG, so `--combined=-` reports every file on stdout (`= ` existing/kept, `+ ` new, `* `/`- `/`! `; names with control characters are escaped, so one line each); `CopyJobQueue._combined_line` takes these lines away from the status parser (a name with ": " would look like a status line) and counts kept ones (first `KEPT_SAMPLE` 1000 names, `copy_kept`; `copy_text` adds "Kept: N existing files"). The Celery tick and the worker's progress/finish (`kept: {count, sample}`, `WORKER_PROTOCOL` 4, validated by `overwrite_policy.record_kept`, first 100 stored) fill `copy_job.skipped_existing` / `skipped_existing_sample`; skip-mode uploads set them at create. `GET /api/copy-jobs/overwrite-policy/` returns only `{overwrite, reason, message}` (404 for other users' connections); upload conflicts return `overwrite`/`overwrite_message` and mode `overwrite` is a 403 when an existing top-level item is outside. Frontend: `NewCopyJobDialog` shows the message per destination, `EditCopyJobDialog` "Existing files" and "Kept" (`utils/overwritePolicy.js`, node test), `UploadConflictDialog` hides "Overwrite all". Known limit: a first copy registers its destination, so a second copy (or Retry) overwrites there. Scheduled runs (scheduled-copies.md) ignore the registry: `overwrite` is False unless `MOTUZ_ALLOW_GENERAL_OVERWRITES` is true.

**AWS egress cost** (README "AWS egress cost"; migration `d2f4a6c8e0b1`, after the overwrite-policy migration `c8e1a3f5d7b9`). `utils/egress_cost.py` (stdlib only) holds the one price table (`INTERNET_TIERS`, `FREE_GB_PER_MONTH`, `INTER_REGION_PER_GB`, `PRICING_DATE` 2026-10; GB = 1e9) and decides: `is_aws` (type s3 and `s3_provider` AWS, or none and no endpoint via `s3_providers.legacy_provider`; a profile only from `~/.aws`, never from an rclone remote, whose own provider wins), `region` (`s3_region`, lower case; empty: `us-east-1`, rclone's default, but unknown (None) for a profile) and `assess(src, dst, runner_region, runs_on)`: rclone moves the data through the machine that runs the job, so a runner not in AWS (or not known to be) means `internet` whatever the destination; in AWS, a destination outside AWS is `internet`, else each region change (read out of the source's region, write into another destination region; unknown regions count as different) is one inter-region leg ($0.02/GB each), none is `same-region` (no confirmation). `egress_manager.runner(pool)`: `central` -> `CENTRAL_AWS_REGION` (`MOTUZ_CENTRAL_AWS_REGION`, validated by `parse_region`; deliberately not `MOTUZ_AWS_REGION`, the EC2 workers' region), the enabled EC2 pool -> its region, other pools -> not in AWS. `copy_estimate` (404 for other users' connections) routes each path with `job_routing.route(..., estimate=)` fed by the one `rclone size` it also prices with (`_Sizes`, as the user, within `EGRESS_SIZE_TIMEOUT` / `MOTUZ_EGRESS_SIZE_TIMEOUT`, 120 s, 5 in the e2e stacks; a timeout routes as large and gives `bytes: null`) and returns the worst path with `runs_on` and `reason`. `hashsum_estimate`: with download every AWS side is read to the runner. `copy_job_manager.create` / `hashsum_job_manager.create` call `confirmed_copy` / `confirmed_hashsum`: if the small or the large route needs a confirmation and the request has no `egress_estimate.confirmed === true`, 400 "Confirm the AWS egress cost in the dialog"; the stored `egress_estimate` takes only bytes/files from the request (they pick the route) and recomputes kind, rates, prices and `runs_on`. Frontend: `CopyJobEgress.jsx` (connected; fetches on mount, spinner, required checkbox, reports `{ready, payload}`; the dialogs disable submit until `ready`, send `payload` as `egress_estimate` and show create errors), texts in `utils/egressCost.js` (with the server's `reason`); `EditCopyJobDialog` / `EditHashsumJobDialog` show the confirmed estimate; Retry reopens the dialog, which asks again.
