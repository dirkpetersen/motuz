# End-to-end tests

Detail for the e2e suites. The command overview is in CLAUDE.md.

End-to-end tests (`test/e2e/`, needs docker and free ports 80, 443, 5000, 5001, 5432, 5672, 5999, 10000; the `worker` suite also needs Docker's `host-gateway` to reach the host's port 443): `run.sh` builds the images with `bin/prod/build.sh`, starts `test/e2e/compose.yml` (the production stack with host networking and Traefik, test users alice/AlicePass1 and bob/BobPass1 from `users.sh`, Azurite, OneDrive/Graph and Google sign-in/Drive API (`/google/...`, `MOTUZ_GDRIVE_*_URL`) pointed at `fake_ms.py` on 127.0.0.1:5999), runs the suites on a fresh database and tears everything down (also on failure). Secrets and the self-signed cert are generated into `test/e2e/.work/` and `test/e2e/.env` (git-ignored); logs go to `test/e2e/logs/`.

Suites are plain scripts (`*_test.py`, `traefik_test.sh`, `ui/ui_test.mjs`, helpers in `common.py`) that print `PASS`/`FAIL`/`SKIP` lines and `<passed>/<total> passed`; `run.sh` prints one summary and exits non-zero if any failed. `e2e` and `broker` expect a fresh database and a fresh fake server (run.sh restarts `fake_ms.py` before each suite that uses it; `oauth-callback` and `ui-callback` first switch the app to an own OneDrive app; `worker`, always last, restarts the app with `MOTUZ_LOCAL_JOB_POOL=onprem`). The `worker` suite (`worker_test.py`) starts the compose profile `worker`: a `motuz-worker` container (`worker_entry.sh`: alice/bob via `users.sh`, an unprivileged `motuz` account with a sudoers rule, credential and CA bundle from `test/e2e/.work/worker/`) on an `internal` Docker network whose only way out is `connect_proxy.py` (CONNECT to `motuz.test:443` only, `motuz.test` = `host-gateway`; the self-signed cert has that SAN). It checks local copy/hashsum jobs on the worker, live progress, Stop, the OneDrive refresh through the HTTPS broker, lease expiry after `docker kill` (`MOTUZ_WORKER_LEASE_SECONDS=20` in compose.yml), and, acting as other workers from the host, auth separation, pool isolation, ticket/broker scope, revocation, `--once` with a bootstrap token, rate limits, that no secret is logged, and that EC2 workers are off (`manage.py ec2`, empty `ec2_worker`, no reaper loop). The UI suites (`ui`: paste-mode sign-ins, credentials picker, dialog layout, the file browser's ages, sorting and viewer (with its follow mode, appending to a log as alice via `docker exec`; images fit/100% and rendered Markdown with the Source switch, locally and on Azurite, fixtures from `viewer_fixtures.py`, which `e2e_test.py` and `cred_test.py` also use for the image endpoint), the New Copy Job dialog's Performance section, in a browser in `America/Los_Angeles` against the UTC containers; `ui-callback`: OneDrive callback sign-in; playwright, `cd test/e2e/ui && npm ci && npx playwright install chromium`) are skipped when node or chromium is missing unless `MOTUZ_E2E_UI=require`; `MOTUZ_E2E_SCREENSHOTS=<dir>` saves a screenshot of each connection dialog state, the panes and the viewer. The credentials suite uses fake AWS keys and skips the checks against real S3 unless `MOTUZ_E2E_AWS_PROFILE` (static keys in `~/.aws/credentials`) and `MOTUZ_E2E_AWS_BUCKET` are set.

`test/e2e/run.sh` and `run_systemd.sh` share `test/e2e/_suites.sh` (fake server, suite runner, summary); the suites reach the installation only through `common.py`'s `sh()`, `psql()`, `pg_dump()` and `service_logs()` (and `appShell()` in `ui/ui_test.mjs`), which switch on `MOTUZ_E2E_TARGET=docker|systemd`.

CI: `.github/workflows/ci.yml` (push and pull_request) runs the backend unit tests, the frontend build, `test/e2e/run.sh` (Docker) and the systemd install twice, `test/e2e/run_systemd.sh --distro=al2027` (container, ~6 min; the job first unloads the runner's AppArmor profile of `unix_chkpwd`, which attaches by path inside containers and breaks PAM in `user@.service`) and `test/e2e/run_systemd.sh` (Ubuntu 26.04 VM with KVM from the udev rule step, image cached, ~9 min), all with `MOTUZ_E2E_UI=require`; no secrets are needed.
