Privacy Policy

Effective date: {{ effective_date }}

Motuz is a web interface for large data transfers between on-premise storage (the file systems of this site) and cloud storage such as Amazon S3, Azure Blob Storage, Google Cloud Storage, OpenStack Swift, Google Drive, Microsoft OneDrive and SharePoint, Dropbox, SFTP and WebDAV servers. Motuz uses the open-source tool rclone to list, copy and verify files. It is used by researchers and staff to move their own data between the storage systems they already have access to.

This policy is provided by the operator of this Motuz installation{% if operator.name %}, {{ operator_name() }}{% endif %} (the "operator", "we"). It describes what data this installation processes, why, how long it is kept and how it is protected. Questions: contact {{ contact() }}.

1. Data we process

Your account

  • Your login name (the Unix / directory user name of this site). Your password is checked at sign-in by the server's operating system (PAM, e.g. against your institution's directory) and is never stored by Motuz.
  • Login tokens: after sign-in the browser receives short-lived tokens that contain your login name. When you sign out, the server records their identifiers as revoked until they would have expired.

Cloud connections

  • The settings of each connection you create: name, type, bucket or container, region, endpoint, account or user name and similar options.
  • The credentials of a connection: access keys, secret keys, passwords, SAS URLs, service account keys and OAuth access and refresh tokens (Google Drive, OneDrive, Dropbox). They are stored on the server in the Motuz database and are never shown again in the browser: the API accepts them but never returns them.
  • Connections created from credentials in your home directory (AWS profiles, rclone remotes, Azure CLI logins) store only the profile name; the keys are read from your own files, as your user, each time they are used.

Transfers and integrity checks (jobs)

  • Source and destination connection and paths, the description you enter, the times a job started and ended, its progress (bytes and files transferred), status, error messages and rclone's output.
  • For integrity checks: the names and checksums of the files that differ between source and destination.
  • The email address you enter for a completion notification, if any.
  • File listings you look at in the file browser (names, sizes, dates) are fetched from the storage when you open a folder and are not stored.

Server logs

  • The web server and the application log requests and operations: your IP address, time, requested address and result, and may include your browser's user agent. Application logs record the operations Motuz runs (for example the rclone commands of your jobs) with credentials masked.

Motuz does not process the contents of your files other than to copy them to the destination you choose and to compute checksums for integrity checks.

2. Google user data (Google Drive)

When you create a Google Drive connection with Sign in with Google, Google asks you to grant Motuz access with the scope https://www.googleapis.com/auth/drive (see, edit, create and delete your Google Drive files). Motuz receives:

  • an OAuth access token and refresh token for your Google account;
  • during sign-in only, your Google account's name and email address and the names of the shared drives you are a member of, so that you can choose which drive the connection uses.

How Motuz uses Google user data. Motuz uses this access only to provide the functions you ask for, and only when you ask for them:

  • it lists files and folders when you browse the Google Drive connection;
  • it reads files when you start a transfer from Google Drive, and creates and writes files and folders when you start a transfer to Google Drive (including creating a folder you ask for);
  • it reads checksums and file contents when you start an integrity check.

A transfer you started keeps running in the background until it finishes or you stop it. Motuz does not scan, index, analyze or monitor your Google Drive on its own, and does not access it at any other time.

Sharing and use restrictions. Google user data is not sold, is not used for advertising, and is not transferred to anyone except to the storage destination that you choose for a transfer (which is the purpose of the transfer) or where required by law. It is not used to develop, improve or train generalized artificial intelligence or machine learning models. People at the operator do not read your Google user data, except with your explicit agreement for specific files (for example when you ask for help), when necessary for security purposes such as investigating abuse, or to comply with applicable law.

Motuz's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage. The tokens are stored in the Motuz database on the operator's server. The refresh token never leaves the server: the rclone processes that run your transfers only receive short-lived access tokens. The account name, email address and drive names from sign-in are discarded after at most 15 minutes, when the sign-in is completed or abandoned. The connection keeps only the identifier of the drive you chose.

Removing access. Delete the connection in Motuz (Connections page): this deletes the stored tokens. You can also revoke Motuz's access at any time at myaccount.google.com/permissions; the connection then stops working.

3. Microsoft user data (OneDrive and SharePoint)

When you create a OneDrive connection with Sign in with Microsoft, Microsoft asks you to grant Motuz delegated Microsoft Graph permissions to read and write your files (Files.ReadWrite.All), to read the SharePoint sites you follow (Sites.Read.All) and to keep this access (offline_access); depending on the app registration also to read your basic profile (User.Read). Motuz receives OAuth access and refresh tokens and, during sign-in, the names of your drives and of the SharePoint sites and document libraries you can choose from.

The same rules as for Google apply: Motuz lists, reads and writes files and folders only when you browse a OneDrive connection or start a transfer or integrity check; it does no automated scanning; Microsoft user data is not sold, not used for advertising, not transferred to anyone except the storage destination you choose, and not used to train AI or machine learning models. Tokens are stored on the server as described above and are deleted when you delete the connection. You can revoke access in your Microsoft account: myapps.microsoft.com for work or school accounts, account.live.com/consent/Manage for personal accounts.

4. Other storage providers

Credentials for other providers (for example S3 keys or SFTP passwords) are used only to list and transfer files as you request, in the same way, and are never shared.

5. Where data goes

Motuz runs on servers of the operator. Your files travel only between the storage systems you select for a transfer. Motuz does not send your data, usage information or credentials to the authors of the Motuz software, to analytics services or to any other third party. The operator's email server sends the notifications you request.

6. Retention

  • Connection settings, credentials and OAuth tokens: until you delete the connection (or the operator removes it, e.g. when your account is closed). Deleting a connection deletes its stored credentials and tokens.
  • Unfinished Google or Microsoft sign-ins: deleted after 15 minutes.
  • Job records: kept so that you can see your transfer history, until the operator deletes them.
  • Records of revoked login tokens: until the tokens would have expired.
  • Server logs: rotated and deleted after a limited time, according to the operator's log retention settings.
  • Database backups, if the operator makes them, follow the operator's backup retention policy.

7. Security

  • All connections to Motuz use HTTPS (TLS 1.2 or newer).
  • Credentials and tokens are write-only in the API and are never sent back to the browser; they are masked in logs.
  • Every connection and job belongs to one user; other users can neither see nor use them.
  • File system operations and transfers run as your own user account on the server, so the operating system enforces your file permissions.
  • OAuth refresh tokens stay on the server; login tokens are short-lived and are revoked when you sign out.

8. Cookies and local storage

Motuz does not use tracking or advertising cookies, analytics or third-party scripts. After you sign in, your browser's local storage keeps your login tokens and a few display settings, so that you stay signed in across tabs; the login tokens are removed when you sign out.

9. Your choices and rights

You can view, change and delete your connections and see your jobs in Motuz at any time. To ask for access to or deletion of other data about you (for example job records or logs), or with any other question about this policy, contact {{ contact() }}. Depending on where you are, you may have further rights under data protection law; the operator handles such requests.

10. Changes

If this policy changes, the new version is published on this page with a new effective date. For significant changes to how Google or Microsoft user data is used, you will be asked for consent again where required.
